# Eval-серии на madharness-mini

Оценка кодинг-агентов: задачи × конфигурации контекста × k повторов, каждый
прогон — свежий workspace + `madharness-mini run` + детерминированная приёмка.
Типовой объём: 8 задач × 3 конфигурации × 5 = 120 прогонов, 6–9 часов.

## Карта полигона (репозиторий эксперимента)

- `fixture/` — полигон (часто отдельный git, НЕ трогать); в нём же — дрейф API.
- `protocol/` — methodology.md (pre-registration, менять только новым коммитом
  с причиной), scenarios/T*.txt, probe-result.md (зонд знаний модели).
- `contexts/` — config.template.json (модель, base_url, temperature, extra_body),
  контексты c0/c1/c2 (AGENTS.md, навыки, V-хуки).
- `scripts/` — make_workspace.sh, run_one.sh (STREAM=<c> → stage CSV),
  batch_drift.sh (25 мин за вызов, circuit breaker), accept/T*.sh (WORKSPACE env).
- `results/` — runs.csv (15 колонок, без заголовка, поле status многострочное),
  stage_c*.csv, logs/, traces/, analysis/.
- `harness/madharness-mini/` — рабочая копия харнесса (см. ниже).

## Харнесс: копия внутри эксперимента

1. Рабочая копия харнесса живёт В директории эксперимента:
   `<repo>/harness/madharness-mini` — свежий клон main
   https://github.com/MADTeacher/madharness-mini (добавить `harness/` в .gitignore).
2. ИСХОДНЫЕ репозитории автора (madharness-mini, madharness-mini-v1 в GitHub/)
   НЕ МОДИФИЦИРОВАТЬ НИКОГДА — это публикуемый код; все патчи только в копии
   `harness/madharness-mini` и фиксируются в methodology.md.
3. Установка: `uv tool install --force <repo>/harness/madharness-mini`.
4. Патч, который должен быть в копии (madharness_mini/model.py, функция chat):
   проброс `extra_body` из конфига в payload и `http_timeout` (120→300 с) —
   см. references/protocol.md.

## Секреты

Ключ API берётся из keyfile (JSON, поле api_key). Ключ НИКОГДА не печатать и
не коммитить. Перед каждым коммитом: `grep -rl "sk-or-v1" .` (и маркеры прочих
провайдеров) — должно быть пусто; если агент прочитал config.json и ключ попал
в трассы/логи — `sed 's/sk-or-v1-[A-Za-z0-9_-]/***/REDACTED***/g'` ДО коммита.

## Порядок серии

1. **Префлайт**: пересобрать workspaces (make_workspace c0/c1/c2), проверить
   temperature, модель, хуки/навыки в workspaces; `py scripts/api_health.py
   <contexts/config.template.json> <keyfile>` до запуска.
2. **Запуск**: три фоновых батча (run_in_background), каждый со СВОИМ staging:
   внешний цикл на поток — `until api_health; do sleep 300; done` перед каждым
   вызовом batch_drift.sh (health-гейт не лечит обрывы внутри прогона, но не даёт
   молотить при лежащем API); внутри batch_drift.sh — circuit breaker: 3 подряд
   rc≠0 → «стоп батча». Останов харнесса: TaskStop НЕ убивает дерево процессов —
   найти PID обёрток по командной строке и убить с //T (//F), родители раньше
   детей, иначе зомби-прогоны пишут мусорные строки.
3. **Мониторинг**: sleep ~570 с + `py progress.py <results>`; сводка для
   пользователя каждые ~40 мин. Bash-таймаут максимум 600 000 мс.
4. **Валидность прогонов**: rc≠0 при acc≠0 — перезапуск (run_one с тем же STREAM,
   keep-last решит при слиянии). rc≠0 при acc=0 — ТОЖЕ перезапуск: сессия
   оборвана средой, приёмка «прошла» на осиротевшем состоянии workspace —
   цензурированный образец нельзя засчитывать. Сомнительная приёмка → 3 замера
   приёмки, вердикт по большинству.
5. **Слияние**: только `py merge_runs.py <results>` (csv-модуль; наивный join
   строк портит файл из-за переводов строк в status). Валидация: все комбинации,
   0 флэков. Успех прогона: rc=0 И accept=0 (accept-скрипт возвращает 0 при сдаче).
6. **Анализ**: p̂ с 95 % ДИ Вильсона по задачам/группам/итогу; активация навыков
   и V-хуки — СТРОГО парсингом JSONL-трасс (событие `skill_activated`, имя на
   верхнем уровне события — `name`/`skill`; блокировки — только события
   `hook_blocked`; текстовый grep завышает на порядки); ходы = max(`turn`) по
   `model_usage`; токены из `model_usage`. Триаж КАЖДОЙ неудачи по логу и трассе:
   (1) дефект контекста / (2) ограничение модели-среды, подкласс stale-knowledge
   (применил несуществующий или @Deprecated API) / (3) флейк среды; доля (1) = q_C.
7. **Отчёт**: results/analysis/final-report-*.md + сравнение с прошлыми сериями
   (их отчёты в results/analysis/ соответствующих репозиториев); главный вопрос
   всегда: даёт ли ЖЦ-контекст прирост именно там, где есть дефицит знания
   (эффект потолка — главный конкурент любой пользы контекста).
8. **Коммит** результатов.

## Стоп-условия (остановиться и сообщить, не выдумывать данные)

Модель недоступна или массово падает приёмка (>50 % одного инстанса);
расхождение матрицы после слияния, не чинящееся перезапусками.

Подробный протокол с командами и примерами: references/protocol.md.
Скрипты: scripts/api_health.py, scripts/progress.py, scripts/merge_runs.py
(копировать в <repo>/scripts при адаптации).

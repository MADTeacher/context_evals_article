# Методика эксперимента drift-eval (Flutter, API-drift)

Версия 1.0, зафиксирована ДО проведения прогонов (pre-registration). Дата: 2026-09-22.
Изменения после первого прогона — только новым коммитом с указанием причины.

## 1. Цель

Проверить гипотезу: **контекст, прошедший жизненный цикл (C2), даёт реальный прирост
успешности тогда, когда он является единственным носителем актуального знания**, т.е.
когда внутренние знания модели об API проекта устарели относительно кода (API-drift).
Дополнительные метрики пользы: расход токенов/времени (стоимость выхода на правильное
решение), доля активаций навыков, срабатывания V-ограничений.

## 2. Полигон и дрейф

- Полигон: lab_8 проекта Mad-Flutter-Practicum (приложение «курсы валют + RSS-новости»,
  Clean Architecture: domain/data/app, provider, go_router-стиль навигации, gen-l10n en/ru).
- Baseline-1 (коммит 49b403f): лаборатория адаптирована под Flutter 3.47.4 (пины
  pubspec, RadioGroup-миграция, pump-фикс теста); analyze 0, тесты 29/29.
- **Дрейф v2 (коммит ce8366f)** — обратно несовместимая эволюция API репозиториев:
  1. `CurrencyRepository.getCurrencyList()` → `fetchRates(CurrencyPageRequest)` →
     `CurrencyPage{items, page, hasMore}`; конвенция проекта: **во всех экранах
     `base: 'USD'`** (значение по умолчанию 'EUR' — ловушка);
  2. `NewsRepository.getNewsList()` → `loadNewsFeed(NewsFeedFilter)`; конвенция
     **свежести**: `forceRefresh: true` — сеть+кэш, `forceRefresh: false` — только кэш;
     паттерн экрана — cache-then-network;
  3. `SettingsRepository.themeMode` → `readThemeMode()`; конвенция: вызывать только
     после `initAsyncData()` (Splash).
- Старые члены сохранены как @Deprecated-шимы (компилируются, `flutter analyze`
  даёт замечание deprecated_member_use). Приёмка требует «No issues found!» —
  т.е. использование шимов = несдача.
- Единственный носитель конвенций v2 — `docs/migration-v2.md` и код; конвенции
  base:'USD', cache-then-network и init-guard в коде не выводимы.

## 3. Конфигурации

- **C0**: полигоны v2 без какого-либо контекста.
- **C1 («сырой» контекст)**: корневой AGENTS.md «за 10 минут» (структура, команды,
  одна строка-указатель на docs/migration-v2.md) + все 10 навыков mad-agents-skills
  как есть (набор БЕЗ flutter-navigation, удалён автором).
- **C2 («после ЖЦ»)**: корневой AGENTS.md по K=(S,A,I,V,Q,P) с маршрутизацией;
  per-dir AGENTS.md в lib/app, lib/data, lib/domain; навык `migration-v2`
  (SKILL.md + references/{currency,news,settings}.md — конвенции и карта кода);
  V-хуки: блокировка использования @Deprecated-членов в новых записях lib/**,
  защита контекстной конфигурации, запрет деструктивных git-команд.

## 4. Задачи и объём

8 задач (protocol/scenarios/T1..T8.txt), по 2 на зону: currency (T1, T2), news (T3, T4),
settings (T5, T6), mixed (T7, T8). Каждая выполняется k=5 раз в каждой конфигурации.
Объём серии: 8 × 3 × 5 = **120 прогонов**. При k=5 пороговые утверждения (p ≥ 0,9)
не делаются — приводятся оценки p̂ и 95 % ДИ Вильсона.

## 5. Приёмка (детерминированная)

Скрипты scripts/accept/T*.sh: `flutter analyze` без замечаний + `flutter test`
все зелёные + структурные проверки задачи (использование новых API-вызовов
с конвенциональными параметрами, отсутствие @Deprecated-членов в lib/**).
Тестовые файлы и код фиксируются в репозитории до серии.

## 6. Протокол прогона

scripts/run_one.sh <T#> <c0|c1|c2> <idx>: свежая копия fixture (HEAD = v2) →
workspaces/run/T#__c#__idx → инжект конфигурации → `madharness-mini run "<постановка>"`
(таймаут 1800 с) → копия трассы → приёмка → строка results/runs.csv.
Модель: deepseek/deepseek-v4.1-flash, temperature 0,8 (решение автора до запуска серии), max_turns 150,
context_max_tokens 256 000.

## 7. Зонд знаний (до серии)

До серии выполняется зонд: модели задаются 3 вопроса о «текущем» API проекта
в workspace без контекста. Ожидание: модель отвечает API v1 (getCurrencyList и т.п.)
— фиксируется дефицит знаний. Если модель отвечает по v2, гипотеза дрейфа
пересматривается до запуска серии.

## 8. Триаж неудач

(1) дефект контекста — конвенция v2 не сообщена контекстом; (2) ограничение
модели/среды — включая новый подкласс **stale-knowledge**: агент применил устаревшее
знание, противоречащее коду; (3) флейк среды. Доля (1) = q_C; (2)+(3) = потолок.

## 9. Дополнение до запуска серии (2026-09-22): смена провайдера API

Серия стартует с нуля (все прогоны до точки смены провайдера удалены как
невалидные — обрывы сессий из-за нестабильности сетевого маршрута к OpenRouter).
Провайдер: OpenRouter → прямой API DeepSeek (https://api.deepseek.com, OpenAI-совместимый),
модель `deepseek/deepseek-v4.1-flash` → `deepseek-flash` (та же версия DeepSeek-V4.1-Flash).
Причина — устойчивая деградация маршрута (повторные обрывы соединений в 3 волны),
не свойства модели. Прочее без изменений: temperature 0,8, max_turns 150, k=5,
приёмка. Технические сопроводительные изменения (madharness-mini v0.1.0):
(а) явное отключение thinking-режима (`thinking: {type: disabled}`) — на прямом API
он включён по умолчанию, тогда как на контрольных прогонах OpenRouter признаков
thinking не было (объёмы completion-токенов и темп вызовов); (б) HTTP-таймаут
запроса поднят 120→300 с (проброс `http_timeout`); (в) проброс доп. параметров
тела запроса из конфига (`extra_body`). Проблема «единственного носителя знания»
от смены провайдера не зависит (зонд protocol/probe-result.md остаётся в силе).

## 10. Дополнение до запуска серии (2026-09-23): расширение на qwen3.6-35b-a3b

Цель — граница применимости по силе агента: полное повторение серии (тот же полигон
lab_8 v2, задачи T1–T8, приёмки, конфигурации C0/C1/C2, k=5; 8 × 3 × 5 = 120 прогонов)
на слабой модели. Единственная содержательная переменная — модель; temperature 0,8 —
как в основной серии. Инференс: локальный OpenAI-совместимый сервер LM Studio
(http://169.254.83.107:13305/v1, модель qwen3.6-35b-a3b-mtp, unsloth GGUF Q4_K_XL,
загруженный контекст 262 144), изоляция эксперимента — отдельная копия репозитория
(flutter-drift-eval-qwen). Отклонения от основной серии, зафиксированные до прогона:
(а) thinking-режим включён — это дефолт модели; средствами API не выключается
(chat_template_kwargs/enable_thinking/reasoning_budget игнорируются сервером,
мягкий переключатель /no_think не действует), рассуждения возвращаются в отдельном
поле reasoning_content и в наблюдаемое агентом содержание не попадают; completion-
токены включают рассуждения — прямое сопоставление абсолютных токенов с основной
серией некорректно, внутрисерийные сравнения C0/C1/C2 остаются валидными;
(б) таймаут прогона 1800 → 3600 с (компенсация замедления от рассуждений);
(в) в chat() харнесса добавлены ретраи HTTP 5xx и сетевых ошибок (до 4 повторов
с паузами 5–90 с; 429 обрабатывается прежним механизмом) — локальный сервер
после длительной сессии может отвечать мгновенным 503, одиночный сбой не должен
ронять прогон; smoke-прогон T1/c0/1 на этой связке прошёл приёмку (613 с);
(г) обнаружен перед запуском серии системный прокси Windows (127.0.0.1:10809),
который stdlib urllib подхватывает из реестра и через него направляет запросы
к 169.254.83.107; прокси отвечает 503 (curl шёл напрямую и показывал 200, поэтому
смоук это не вскрыл). Исправление среды, на методику не влияет: base_url переключён
на http://127.0.0.1:13305/v1 (сервер слушает на всех интерфейсах, localhost
байпасится прокси по умолчанию — проверено дефолтным opener'ом urllib) плюс
страховочный прямой запрос без прокси (ProxyHandler({})) в chat() харнесса
и в scripts/api_health.py;
(д) пополнение в ходе серии (2026-09-23, ~05:30, после 24 прогонов): таймаут
прогона 3600 → 5400 с. Причина: два цензурированных прогона T2/c2/4 и T2/c2/5
(rc=124 по таймауту при формально пройденной приёмке на осиротевшем состоянии —
такие образцы по протоколу не засчитываются). Диагноз: не деградация движка
(state loaded, 503 нет), а насыщение локального инференса тремя параллельными
сессиями с thinking-режимом: хвост распределения длительности у C2 (наибольший
контекст) упирается в потолок. Правка снимает цензуру, на сравнение конфигураций
не влияет (таймаут одинаков для всех конфигураций), абсолютные длительности
с локальным инференсом всё равно не сопоставляются с основной серией.
Зонд знаний (protocol/probe-result-qwen.md, до серии): точный API lab_8 модели
неизвестен — ни v2 (fetchRates/loadNewsFeed/readThemeMode), ни точный v1; на вопрос
о курсах валют уверенно сконструирован вымышленный сервис (CurrencyApiService.
getRates()), на вопросы о новостях и теме — отказ от конкретики и общие паттерны.
Предпосылка дефицита знаний подтверждена, с подклассом «уверенная галлюцинация».

## 11. Итерация жизненного цикла C2 (зарегистрировано 2026-09-23, до прогона итерации 2)

По завершении серии итерации 1 (120/120, 0 флэйков после перезапусков; итог:
C0 13/40, C1 18/40, C2 14/40) выполнен триаж всех 75 неудач: для каждого
прогона воспроизведён упавший чек приёмки и разобрана трасса. Ключевые
классы причин: (а) «слепая верификация» — инструмент run_shell исполняет
команду без shell (subprocess + shlex.split), на Windows форма `flutter`
не резолвится CreateProcess'ом (WinError 2; flutter присутствует как .bat),
пайпы/редиректы/`;`/`&&` запрещены политикой — ни один агент qwen ни в одной
конфигурации не выполнил ни одного успешного flutter-вызова (в T1 — все
попытки всех прогонов), при этом C2 (I.6) предписывал `flutter analyze`/
`flutter test`, не сообщая рабочей формы: агенты сжигали ходы на вариантах,
заявляли верификацию без вывода или переносили её на пользователя; для
сравнения: deepseek в той же среде самостоятельно находил форму `flutter.bat`
(754 успешных вызова в 82 прогонах из 120) — сильная модель компенсирует
дефицит знания среды из весов, слабая нет; (б) правка `assets/l10n/*.arb`
без регенерации (`gen-l10n`) — undefined getter при компиляции; (в) остаточные
неиспользуемые импорты/поля — критерий «No issues found!» требует нуля
замечаний любого уровня; (г) прочие дефекты кода слабой модели (типы,
константы, синтаксис, недоделанная пагинация).

Эволюция C2 — правки только в contexts/c2 (контекст v2, версия навыка
migration-v2 2.0-eval): I.6 и Q переведены на исполняемые формы
(`flutter.bat`/`dart.bat`) с требованием фактического вывода верификации;
добавлен раздел «Среда исполнения» (отсутствие shell, запрет пайпов,
рабочие формы, трактовка FileNotFoundError); добавлено I.7 (правка ARB →
`flutter.bat gen-l10n` → analyze/test); Q уточняет буквальность «No issues
found!». C0 и C1 заморожены. Гипотеза итерации 2: успешность C2 растёт
(прежде всего T1/T2, где доминируют (а)–(в)); изменения C0/C1 исключены
по построению.

Процедура итерации 2: пересборка workspaces/c2 из fixture v2 (ce8366f) с
эволюционированным контекстом; полный повтор 40 прогонов C2 (T1–T8 × k=5),
те же сценарии и приёмки, temperature 0,8, max_turns 150, таймаут 5400 с.
Результаты C2 итерации 1 архивируются в results/iter1/ и в слияние
итерации 2 не включаются; сопоставление «до/после» — по одинаковым задачам
и приёмкам. Признак содержательности: статистически и практически значимый
прирост C2 без роста длительности/токенов сверх ожиданий от верификации.

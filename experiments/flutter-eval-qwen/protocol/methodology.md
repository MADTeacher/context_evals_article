# Методика эксперимента drift-eval (Flutter, API-drift, слабая модель)

Версия 1.1-qwen, зафиксирована ДО проведения прогонов (pre-registration).
Дата: 2026-09-24. Наследует дизайн v3 (single-carrier) из sibling-эксперимента
flutter-eval-deepseek (методика v1.1): аудит его итерации 1 (v2-полигон) показал,
что предпосылка «единственного носителя знания» не реализовалась — конвенции v2
выводимы из самого репозитория (docs/migration-v2.md в репо, образцы вызовов
в экранах, тексты @Deprecated-шимов, base:'USD' в сценарии T2), и C0 достиг
0,93 при контрасте C2−C0 = −0,03. Итерация 2 там же (v3-полигон) дала
C0 0,50 / C1 0,57 / C2 0,93, C2−C0 = +0,43. Настоящая серия повторяет дизайн
v3 на слабой локальной модели (граница применимости по силе агента).
Изменения методики после фиксации — только новым коммитом с указанием причины.

## 1. Цель

Проверить гипотезу: **контекст, прошедший жизненный цикл (C2), даёт реальный прирост
успешности тогда, когда он является единственным носителем актуального знания**, т.е.
когда внутренние знания модели об API проекта устарели относительно кода (API-drift).
Назначение серии — граница применимости гипотезы по силе агента: тот же дизайн
на слабой модели. Дополнительные метрики пользы: расход токенов/времени (стоимость
выхода на правильное решение), доля активаций навыков, срабатывания V-ограничений.

## 2. Полигон и дрейф

- Полигон: lab_8 проекта Mad-Flutter-Practicum (приложение «курсы валют + RSS-новости»,
  Clean Architecture: domain/data/app, provider, go_router-стиль навигации, gen-l10n en/ru).
- Baseline-1 (коммит 49b403f): лаборатория адаптирована под Flutter 3.47.4 (пины
  pubspec, RadioGroup-миграция, pump-фикс теста); analyze 0, тесты 29/29.
- **Дрейф v2 (коммит ce8366f)** — обратно несовместимая эволюция API репозиториев:
  1. `CurrencyRepository.getCurrencyList()` → `fetchRates(CurrencyPageRequest)` →
     `CurrencyPage{items, page, hasMore}`; конвенция проекта: **во всех экранах
     `base: 'USD'`** (значение по умолчанию 'EUR' — ловушка);
  2. `NewsRepository.getNewsList()` → `loadNewsFeed(NewsFeedFilter)`; конвенция
     **свежести**: `forceRefresh: true` — сеть+кэш, `forceRefresh: false` — только кэш;
     паттерн экрана — cache-then-network;
  3. `SettingsRepository.themeMode` → `readThemeMode()`; конвенция: вызывать только
     после `initAsyncData()` (Splash).
- Старые члены сохранены как @Deprecated-шимы (компилируются, `flutter analyze`
  даёт замечание deprecated_member_use). Приёмка требует «No issues found!» —
  т.е. использование шимов = несдача.
- **Дрейф v3 (коммит ebf17f9)** — устранение побочных носителей конвенций из
  полигона: (1) `docs/migration-v2.md` удалён; (2) экран курса и юнит-тесты
  репозитория вызывают `fetchRates` с default-base (без 'USD'); (3) тексты
  @Deprecated-шимов не указывают замены; (4) changelog-фрагменты не содержат
  значений конвенций. Единственный носитель конвенций v2 — контекст C2
  (навык migration-v2 + K-структура AGENTS.md). Контроль утечек —
  `py scripts/leak_scan.py` (жёсткие маркеры request-конвенции: пусто).
  Слабая конвенция: семантика forceRefresh частично выводима из имени флага и
  постановок T3/T4 — признано допустимым; дискриминирующая нагрузка —
  конвенции base:'USD' (T1/T2) и init-guard (T5/T6).

## 3. Конфигурации

- **C0**: полигоны v3 без какого-либо контекста.
- **C1 («сырой» контекст)**: корневой AGENTS.md «за 10 минут» (структура, команды,
  общие правила; указатель на docs/migration-v2.md убран вместе с самой докой)
  + все 10 навыков mad-agents-skills
  как есть (набор БЕЗ flutter-navigation, удалён автором).
- **C2 («после ЖЦ»)**: корневой AGENTS.md по K=(S,A,I,V,Q,P) с маршрутизацией;
  per-dir AGENTS.md в lib/app, lib/data, lib/domain; навык `migration-v2`
  версии 2.0-eval (SKILL.md + references/{currency,news,settings}.md — конвенции
  и карта кода); I.6 и Q требуют исполнимой верификации с фактическим выводом
  (рабочие формы команд `flutter.bat`/`dart.bat`), I.7 — цепочка «правка ARB →
  `flutter.bat gen-l10n` → analyze/test», раздел «Среда исполнения» (отсутствие
  shell, запрет пайпов/редиректов, рабочие формы команд, трактовка
  FileNotFoundError); V-хуки: блокировка использования @Deprecated-членов в новых
  записях lib/**, защита контекстной конфигурации, запрет деструктивных git-команд.

## 4. Задачи и объём

8 задач (protocol/scenarios/T1..T8.txt), по 2 на зону: currency (T1, T2), news (T3, T4),
settings (T5, T6), mixed (T7, T8). Каждая выполняется k=5 раз в каждой конфигурации.
Объём серии: 8 × 3 × 5 = **120 прогонов**. При k=5 пороговые утверждения (p ≥ 0,9)
не делаются — приводятся оценки p̂ и 95 % ДИ Вильсона.

## 5. Приёмка (детерминированная)

Скрипты scripts/accept/T*.sh: `flutter analyze` без замечаний + `flutter test`
все зелёные + структурные проверки задачи (использование новых API-вызовов
с конвенциональными параметрами, отсутствие @Deprecated-членов в lib/**).
Тестовые файлы и код фиксируются в репозитории до серии.

Инвариант (v1.1, унаследован из deepseek v1.1): каждая приёмка обязана падать
на нетронутой фикстуре (проверка перед серией на свежем workspaces/c0);
нарушение = приёмка не проверяет задачу. Приёмка T3 усилена требованием кнопки
«Обновить» в news_list_page.dart (в deepseek-итерации 1 T3 проходила на чистой
фикстуре).

## 6. Протокол прогона

scripts/run_one.sh <T#> <c0|c1|c2> <idx>: свежая копия fixture (HEAD = v3, ebf17f9) →
workspaces/run/T#__c#__idx → инжект конфигурации → `madharness-mini run "<постановка>"`
(таймаут 5400 с) → копия трассы → приёмка → строка results/runs.csv.
Модель: qwen3.6-35b-a3b-mtp (LM Studio, локальный инференс, см. раздел 9),
temperature 0,8 (решение автора до запуска серии), max_turns 150,
context_max_tokens 256 000.

## 7. Зонды до серии

1. **Зонд знаний (выполнен)**: модели заданы 3 вопроса о «текущем» API проекта
   в workspace без контекста. Результат — protocol/probe-result-qwen.md: точный
   API lab_8 модели неизвестен (ни v2, ни точный v1); на вопрос о курсах валют
   уверенно сконструирован вымышленный сервис (CurrencyApiService.getRates()),
   на вопросы о новостях и теме — отказ от конкретики. Предпосылка дефицита
   знаний подтверждена, с подклассом «уверенная галлюцинация».
2. **Зонд выводимости (обязателен до серии)**: 3 агента C0 на самой
   конвенционно-зависимой задаче (T1: конвенция base:'USD' невыводима из
   v3-полигона) — `bash scripts/probe_derive.sh 3 T1`. Гейт: ≥2 из 3 сдали
   приёмку → конвенция выводима из репозитория, полигон течёт: СТОП и разбор
   утечки (leak_scan + трассы), серия не запускается. ≤1 из 3 → серия стартует.
   Эталон для сравнения: deepseek-итерация 2 — зонд 0/3 (все три агента выполнили
   задачу полностью, упав ровно на grep 'USD').

## 8. Триаж неудач

Дизайн v3: v2-итерация (конвенции выводимы из репо) проведена в
flutter-eval-deepseek (results/iter1 — негативный контроль); qwen-серия
стартует сразу на v3-полигоне, results/ не содержит прошлых серий.
Для C0/C1 класс (1) — ожидаемый эффект single-carrier, а не дефект артефакта.

(1) дефект контекста — конвенция v2 не сообщена контекстом; (2) ограничение
модели/среды — включая подкласс **stale-knowledge**: агент применил устаревшее
знание, противоречащее коду; (3) флейк среды. Доля (1) = q_C; (2)+(3) = потолок.

## 9. Инференс и среда исполнения

- Инференс: локальный OpenAI-совместимый сервер LM Studio, модель
  qwen3.6-35b-a3b-mtp (unsloth GGUF Q4_K_XL), загруженный контекст 262 144;
  base_url `http://127.0.0.1:13305/v1` (адрес через 127.0.0.1 — системный прокси
  Windows не перехватывает localhost; дополнительно в chat() харнесса и
  scripts/api_health.py выполняется прямой запрос без прокси, ProxyHandler({})).
- thinking-режим включён (свойство модели qwen3.6-35b-a3b-mtp) и средствами API
  не выключается: попытка chat_template_kwargs enable_thinking: false не даёт
  эффекта и удалена из конфигурации; рассуждения возвращаются в отдельном
  поле reasoning_content и в наблюдаемое агентом содержание не попадают;
  completion-токены включают рассуждения — учитывать при интерпретации
  метрик расхода.
- Таймаут прогона 5400 с, единообразно для всех конфигураций (медленный локальный
  инференс с рассуждениями; цензурированные по таймауту образцы не засчитываются).
- В chat() харнесса — ретраи HTTP 5xx и сетевых ошибок (до 4 повторов с паузами
  5–90 с; HTTP 429 обрабатывается отдельным механизмом rate-limit).

## 10. Итерации при эволюции C2

Если C2 систематически недотягивает и триаж неудач указывает на дефекты
контекста класса (1), автор может принять решение об эволюции ЖЦ-контекста.
Эволюция — только доказательная, из трасс серии. Протокол итерации
(закреплён до старта серии):
1. Основание эволюции — сравнительный анализ трасс (досье): (а) C0 —
   поведение агента без контекста (что знает/не знает об API, где
   спотыкается); (б) C1 — что меняет сырой AGENTS.md; (в) неудачи C2 —
   паттерны и закономерности: какие конвенции v2 контекст не сообщил,
   сообщил не в той форме или сделал неисполнимыми для агента. Каждое
   изменение новой версии C2 обязано ссылаться на конкретный паттерн из
   трасс; досье сохраняется в analysis/ итерации.
2. Эволюция C2 — отдельным коммитом: правка contexts/c2, инкремент версии C2
   (текущая — 2.0-eval), причина и связь с паттернами досье — в этот раздел
   методики.
3. Итоги текущей итерации архивируются ДО перезапуска переносом (не
   копированием) в results/iter<N>/: runs.csv, stage_c2.csv, трассы и логи
   c2-прогонов, analysis/ (трассы и логи C0/C1 остаются на месте — их
   конфигурации не менялись).
4. Перезапускается только поток C2 с той же моделью (STREAM=c2); результаты
   C0/C1 переносятся в матрицу новой итерации без перезапуска. Слияние
   keep-last по (T, config, idx) перезапишет только строки c2.
5. Отчёт итерации обязан включать сравнение с предыдущей по архиву:
   p̂, токены, длительность до/после эволюции — и проверку: ушли ли паттерны,
   мотивировавшие изменения.
